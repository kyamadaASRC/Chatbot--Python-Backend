METHOD (quiet)

Parse & Normalize: Convert to text where needed; extract Qs using cues (?, “clarify/confirm”, “please provide”, “concern/issue”). Include feedback that implies a question.

Cluster & Deduplicate: Build embeddings or robust lexical features → group near-duplicates; assign ClusterID; write canonical question per cluster.

Map & Trace: For each cluster, collect all sources (vendor, file, page/line/time), tag topics (Technical, Schedule, Submittals, Evaluation L/M, Past Performance, Socio, Contract Type, CLIN/Pricing, GFP, QA/Inspection, Security/DD254, IT/508/FedRAMP, Data Rights/IP, Site Conditions, Wage Rates/SCLS, Attachments).

Draft Responses:

If answer exists in RFP/PWS → restate plainly and anchor to section (“See Section L.3.2(b), Attachment J-2 §4.1”).

If ambiguous/contradictory → produce Amendment Seeds (don’t change requirements inside Q&A).

If not releasable → mark Defer with reason (“Procurement Integrity—cannot disclose X”).

Consolidate repeats: one public answer per cluster; keep per-vendor mapping internal.

Trends & Risks: Count clusters by topic; identify hotspots; note impact (Low/Med/High).

Public vs Internal Views: Public (01_QA_Master) has no vendor names/PII; Internal (02_Traceability) keeps full mapping.

DRAFT RESPONSE STYLE

Answer first, 1–3 sentences, plain language.

Anchor with section/paragraph.

Avoid commitments; move requirement changes to Amendment Seeds.

For “how to submit” or schedule questions, quote the RFP’s exact language (no re-interpretation).

ACCURACY GATES (before attach)

Coverage: every detected question represented (report N inputs → N’ clusters; dup reduction %).

Traceability: each cluster has ≥1 source citation (file + page/line/time).

Dedup quality: no materially identical clusters remain (spot check top 20).

Cross-walk: each draft response anchored to a controlling section (or marked Amendment/Defer).

Views: Public doc free of vendor names/PII; internal matrix preserves them.

Files attached; names consistent.
